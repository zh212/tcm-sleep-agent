# 第二阶段设计：关键词检索版轻量 RAG Demo

## 1. 背景与阶段目标

当前项目第一阶段已经完成最小闭环 Demo：用户在 Streamlit 页面输入失眠相关症状，系统调用 DeepSeek 在线模型，并返回中医辅助分析文本。

第二阶段不直接引入向量数据库、Embedding 模型或复杂 Agent 框架，而是优先把系统从“纯模型调用”升级为“有本地知识依据的轻量 RAG Demo”。

第二阶段目标：

> 建立一个小型本地中医失眠方剂/证型知识库，通过关键词检索召回相关知识片段，再把召回内容交给 DeepSeek 生成结构化辅助分析，并在页面展示检索依据。

完成后，系统应能被准确描述为：**关键词检索版 RAG 原型 Demo**。它仍然是课程演示系统，不是临床诊疗系统。

## 2. 范围

### 2.1 本阶段包含

- 新增本地中医失眠方剂/证型样例知识库。
- 新增关键词检索模块。
- 将检索结果注入 DeepSeek 提示词。
- 让模型基于检索结果生成结构化回答。
- 在 Streamlit 页面展示 RAG 执行过程和检索依据。
- 保留医疗免责声明和辅助参考定位。

### 2.2 本阶段不包含

- 不接入 FAISS、Chroma、Milvus 等向量数据库。
- 不接入 embedding 模型。
- 不做 Cross-Encoder reranker。
- 不实现真正动态 Few-shot。
- 不做真实病历数据治理。
- 不做完整安全规则引擎。
- 不做后端服务拆分。
- 不做临床级处方剂量推荐。

## 3. 推荐方案

采用 **关键词检索 RAG**。

整体流程：

```text
用户输入失眠症状
    ↓
Streamlit 页面接收输入
    ↓
关键词检索模块读取本地知识库
    ↓
按症状、证型、功效、方剂名称等字段计算匹配分数
    ↓
返回 Top 3 条相关方剂/证型知识
    ↓
LLM 生成模块把“用户输入 + 检索知识”发送给 DeepSeek
    ↓
DeepSeek 输出结构化辅助分析
    ↓
页面展示分析结果、检索依据、执行过程和免责声明
```

选择该方案的原因：

- 与当前第一阶段代码衔接最平滑。
- 不增加复杂环境依赖，适合 Windows 本地快速演示。
- 能明显体现“知识库 + 检索增强”的项目核心特征。
- 后续可以把关键词检索模块替换为向量检索模块，而不需要推翻 UI 和 LLM 生成逻辑。

## 5. 知识库设计

知识库使用 JSON 文件，先维护 10 条左右失眠相关中医方剂/证型样例。

每条数据建议包含：

```json
{
  "id": "guipi-tang",
  "name": "归脾汤",
  "syndrome": "心脾两虚",
  "symptoms": ["失眠", "多梦", "心悸", "健忘", "食少", "乏力"],
  "effects": "益气补血，健脾养心",
  "ingredients": ["党参", "白术", "黄芪", "当归", "酸枣仁", "龙眼肉", "远志", "木香", "甘草"],
  "notes": "课程演示知识，不作为真实处方依据。"
}
```

建议首批知识包括：

1. 酸枣仁汤：肝血不足，虚热内扰。
2. 归脾汤：心脾两虚。
3. 天王补心丹：心肾阴虚。
4. 温胆汤：痰热扰心。
5. 黄连阿胶汤：阴虚火旺，心肾不交。
6. 甘麦大枣汤：心脾血虚，脏躁。
7. 安神定志丸：心胆气虚。
8. 朱砂安神丸：心火亢盛。
9. 柴胡加龙骨牡蛎汤：肝郁化火，烦躁惊悸。
10. 柏子养心丸：心气不足，心血亏虚。

知识库中的内容只作为课程演示样例，不作为真实临床处方依据。

## 6. 检索模块设计

`src/retriever.py` 负责本地知识检索。

建议暴露一个主要函数：

```python
retrieve_formulas(user_input: str, top_k: int = 3) -> list[dict]
```

职责：

1. 读取 `data/insomnia_formulas.json`。
2. 将用户输入与每条知识的以下字段做关键词匹配：
   - 方剂名称；
   - 证型；
   - 症状列表；
   - 功效；
   - 注意事项。
3. 为每条知识计算简单匹配分数。
4. 返回得分最高的 Top K 条。
5. 每条返回结果应包含：
   - 原始方剂信息；
   - 匹配分数；
   - 命中的关键词或症状。

基础评分规则可以保持简单：

- 命中症状关键词：加 2 分。
- 命中证型关键词：加 2 分。
- 命中方剂名称、功效或注意事项：加 1 分。
- 如果没有任何命中，返回若干通用失眠相关条目，并标记为低置信度。

该模块不负责调用大模型，也不负责页面展示。

## 7. LLM 生成模块设计

`src/llm.py` 在第二阶段继续负责 DeepSeek 调用，但需要从“只接收用户输入”升级为“接收用户输入 + 检索结果”。

建议将当前函数升级为：

```python
chat_with_deepseek(user_input: str, retrieved_items: list[dict]) -> str
```

提示词要求：

- 明确说明当前系统是课程 Demo。
- 要求模型只能基于检索到的知识做辅助分析，不能编造知识库之外的方剂。
- 输出结构化内容：
  1. 症状摘要；
  2. 可能证型；
  3. 参考方剂；
  4. 推荐理由；
  5. 检索依据；
  6. 注意事项；
  7. 医疗免责声明。
- 不给出真实临床剂量。
- 不宣称可以替代医生。

如果检索结果为空或低置信度，模型应明确说明“当前知识库未检索到高度匹配内容”，并只给出谨慎的学习性分析。

## 9. 错误处理

第二阶段至少处理以下情况：

- 用户输入为空：提示用户先输入失眠相关症状。
- `.env` 未配置 API Key：保留当前错误提示。
- 知识库文件不存在或 JSON 解析失败：在页面提示“知识库加载失败”。
- 检索无明显命中：返回低置信度通用条目，并在页面或输出中说明匹配不足。
- DeepSeek 调用失败：页面展示调用失败原因，不隐藏错误。

- 医疗免责声明保留。

## 12. 后续升级方向

第二阶段完成后，后续可以继续推进：

1. 将关键词检索替换或扩展为 embedding + 向量检索。
2. 加入 BM25 + 向量混合召回。
3. 加入 reranker。
4. 加入动态 Few-shot 示例选择。
5. 加入症状—草药频率映射表。
6. 加入“十八反”“十九畏”等安全规则检查。
7. 加入离线评测脚本。

这些内容不进入第二阶段实现范围。第二阶段只负责把轻量 RAG 链路跑通。
