# 3. 当前运行流程总览

从用户访问网页到看到结果，完整流程如下：

```text
1. 用户打开 http://127.0.0.1:8501
   ↓
2. Streamlit 运行 app.py
   ↓
3. app.py 显示标题、提示、输入框、按钮
   ↓
4. 用户在文本框输入失眠症状
   ↓
5. 用户点击“开始分析”按钮
   ↓
6. app.py 调用 src.llm.chat_with_deepseek(user_input)
   ↓
7. chat_with_deepseek() 清理输入、读取模型名、创建 DeepSeek 客户端
   ↓
8. 程序通过 OpenAI SDK 的兼容接口请求 DeepSeek API
   ↓
9. DeepSeek 返回文本结果
   ↓
10. app.py 用 st.markdown(result) 把结果显示到页面
```

当前版本没有知识库，所以模型回答主要来自 DeepSeek 自身能力和我们写的 Prompt。

后续加入 RAG 后，流程会变成：

```text
用户输入症状
→ 检索本地方剂知识库
→ 把检索结果和用户症状一起发给 DeepSeek
→ DeepSeek 基于知识库生成结构化建议
→ 页面展示建议和检索依据
```

# 4. `src/llm.py` 代码详细讲解

当前完整代码：

```python
"""DeepSeek API wrapper for the first Streamlit MVP."""

import os

from dotenv import load_dotenv
from openai import OpenAI


load_dotenv()


SYSTEM_PROMPT = """你是一个中医失眠处方辅助 Demo 的说明型助手。
当前系统仍处于课程演示阶段，不能替代医生诊断，也不能给出真实处方。
请用中文回答，语气清晰、谨慎、适合课堂项目演示。
"""


def get_deepseek_client() -> OpenAI:
    """Create an OpenAI-compatible client configured for DeepSeek."""
    api_key = os.getenv("DEEPSEEK_API_KEY")
    base_url = os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com")

    if not api_key or api_key == "replace_with_your_deepseek_api_key":
        raise RuntimeError("请先在 .env 文件中配置 DEEPSEEK_API_KEY。")

    return OpenAI(api_key=api_key, base_url=base_url)


def chat_with_deepseek(user_input: str) -> str:
    """Send a symptom description to DeepSeek and return the assistant text."""
    cleaned_input = user_input.strip()
    if not cleaned_input:
        raise ValueError("请输入失眠相关症状后再开始分析。")

    model = os.getenv("DEEPSEEK_MODEL", "deepseek-chat")
    client = get_deepseek_client()

    response = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {
                "role": "user",
                "content": (
                    "用户输入的失眠相关症状如下：\n"
                    f"{cleaned_input}\n\n"
                    "请先做一个简短的中医辅助分析示例，输出包括：\n"
                    "1. 症状摘要\n"
                    "2. 可能的中医分析方向\n"
                    "3. 后续系统接入 RAG 知识库后可以如何进一步分析\n"
                    "4. 医疗免责声明\n"
                    "注意：不要给出真实处方剂量，不要声称可以替代医生。"
                ),
            },
        ],
        temperature=0.3,
    )

    return response.choices[0].message.content or "模型未返回内容。"
```

- 值越低，回答越稳定；
- 值越高，回答越发散。

医疗类 Demo 建议低一些，所以这里设为 `0.3`。

### 4.8.9 返回模型内容

```python
return response.choices[0].message.content or "模型未返回内容。"
```

DeepSeek 返回结果后，文本内容在：

```python
response.choices[0].message.content
```

如果没有内容，就返回：

```text
模型未返回内容。
```

# 8. 当前项目的关键设计思想

## 8.1 页面和模型调用分离

`app.py` 不直接写 DeepSeek API 细节，而是调用：

```python
chat_with_deepseek(user_input)
```

好处：后面改模型、加 RAG、加 Agent 时更容易维护。

---

## 8.2 API Key 不写死在代码里

API Key 放在 `.env` 中，而不是写在 `.py` 文件里。

好处：

1. 更安全；
2. 方便换 Key；
3. 代码可以分享，Key 不会泄露。

---

## 8.3 医疗免责声明前置

页面一打开就显示：

```text
本系统仅用于课程学习和技术演示，不构成真实医疗诊断或处方建议。
```

原因：这是医疗相关系统，必须明确边界。

---

## 8.4 Prompt 中限制模型输出

在 `SYSTEM_PROMPT` 和用户 Prompt 中都强调：

- 不替代医生；
- 不给真实处方；
- 不给真实剂量；
- 仅做课程演示。

这样可以减少医疗风险，也更符合项目定位。
