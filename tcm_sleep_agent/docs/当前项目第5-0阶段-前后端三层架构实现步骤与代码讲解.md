## 一、背景与目标

**为什么要拆前后端？**

V4 是 Streamlit 一体式应用——UI 渲染、业务逻辑、数据库读写、LLM 调用全在一个 Python 进程里。这种结构在原型阶段没问题，但存在四个"天花板"：

1. **单用户**：Streamlit 的 session state 是进程内的，多用户开不了
2. **无法被其他系统调用**：医院 HIS 系统想接入？做不到，没有 API
3. **前后端耦合**：改一行 UI 可能影响业务逻辑
4. **无法独立部署**：前后端只能同机运行

第五阶段把它拆成：

```text
Streamlit 前端 ─── HTTP ───► FastAPI 后端 ───► SQLite + Chroma
```

前端只管"画界面 + 发请求"；后端只管"接请求 + 跑业务 + 返数据"；数据库只管"存东西"。**关注点彻底分离**。

## 二、核心概念速通

### 2.1 什么是"后端"

后端 = **一个常驻运行的程序，监听某个端口（比如 8000），接收 HTTP 请求，返回数据**。

工作模式：

1. 你启动 `uvicorn`，它开始监听 `127.0.0.1:8000`
2. 前端发一个 HTTP 请求过来，比如 `POST /search`，请求体是 `{"query": "失眠", "top_k": 5}`
3. FastAPI 找到你写的 `def semantic_search(...)` 函数，把参数传进去执行
4. 函数返回的 Python 对象自动转成 JSON，发回给前端

**关键变化**：以前是同一进程内直接 `search("失眠")` 函数调用；现在是**跨进程、跨网络**通信。

### 2.2 什么是 REST API

REST API = **一种前后端约定好的通信规则**。前端发某种 HTTP 请求，后端返 JSON。就这么简单。

四种常见 HTTP 方法（你只要先记两种）：

- **GET** — 查数据（`GET /knowledge/count` 查知识库条目数）
- **POST** — 提交数据/触发动作（`POST /analyze` 提交症状，触发分析）

一个完整请求包含四要素：

- **方法**：GET / POST
- **路径**：`/analyze`、`/knowledge/123`
- **请求体**（POST/PUT 才有）：JSON 数据
- **响应**：状态码（200/404/422/500）+ JSON 响应体

### 2.3 FastAPI vs uvicorn

一个常见困惑：为什么装了 FastAPI 还要装 uvicorn？

- **FastAPI** = 框架（教你怎么写接口，比如 `@app.get(...)`）
- **uvicorn** = 服务器（真正监听端口、收 HTTP 请求、把请求转给 FastAPI）

打个比方：FastAPI 是餐厅的菜单和厨师；uvicorn 是餐厅的前台服务员，负责接客并把订单送到后厨。

命令 `uvicorn backend.main:app` 意思是：

- `backend.main` = 找 `backend/main.py` 文件
- `:app` = 在里面找那个叫 `app` 的对象

### 2.4 数据库层没有变

第五阶段**没有换数据库**。SQLite 和 Chroma 都保持不变，仍然是 V4 那套。

变化的是：数据库操作的位置从 Streamlit 里挪到 FastAPI 里。前端已经完全"摸不到"数据库。

## 四、Task 1 · 后端骨架

**目标**：装依赖、建目录、跑起一个能返回 `{"status":"ok"}` 的最小后端。

### 4.1 依赖清单

`requirements.txt` 新增：

```text
fastapi>=0.110.0
uvicorn[standard]>=0.29.0
pydantic>=2.6.0
httpx>=0.27.0
pytest>=8.0.0
```

- `fastapi` — 框架
- `uvicorn[standard]` — 服务器（`[standard]` 表示带上性能优化的依赖，比如 `httptools`）
- `pydantic` — 数据校验
- `httpx` — 前端发 HTTP 用（也是 pytest TestClient 底层用的）
- `pytest` — 测试框架

### 4.2 最小后端 `backend/main.py`

```python
"""FastAPI backend entry for TCM Sleep Agent."""

from fastapi import FastAPI

app = FastAPI(
    title="中医失眠处方智能辅助系统 API",
    description="省级大创项目 · RAG + 动态 Few-shot 后端服务",
    version="0.5.0",
)


@app.get("/health")
def health() -> dict:
    """Health check endpoint."""
    return {"status": "ok", "service": "tcm-sleep-agent-backend"}
```

**逐行解释**：

- `app = FastAPI(...)` — 创建应用对象。`title / description / version` 会显示在自动生成的 `/docs` 页面上。
- `@app.get("/health")` — 装饰器。它在告诉 FastAPI："当有人 `GET /health` 时，请调用下面这个函数"。
- `def health()` — 就是普通 Python 函数。返回什么，FastAPI 就把它转成 JSON 发回去。

### 4.3 启动命令

```powershell
uvicorn backend.main:app --reload --port 8000
```

- `--reload` — 代码改动后自动重启（开发时用）
- `--port 8000` — 监听 8000 端口

启动后访问：

- `http://127.0.0.1:8000/health` → JSON 响应
- `http://127.0.0.1:8000/docs` → **自动生成的交互式 API 文档**（Swagger UI）

**杀手锏**：`/docs` 页面能直接在浏览器上"点按钮调接口"，输入参数、看响应、复制 curl 命令。这是 FastAPI 相对于其他 Python 后端框架最大的优势之一。

### 4.4 `__init__.py` 是什么

`backend/__init__.py`、`backend/routers/__init__.py` 都是空文件。

Python 里，一个文件夹只要有 `__init__.py`（哪怕空），就被认为是一个"包"。有了它才能写 `from backend.main import app` 这种跨文件夹导入。

## 五、Task 2 · Pydantic 数据契约

**目标**：定义每个接口"进来的数据形状"和"出去的数据形状"。

### 5.1 什么是 Pydantic

Pydantic 是 Python 里做 **"数据形状定义 + 自动校验"** 的库。你用类的语法定义"这个数据应该长什么样"，Pydantic 会：

1. 自动检查类型（`int` 传成字符串会报错）
2. 自动检查约束（`min_length=1`、`ge=1`、`le=20`）
3. 自动转 JSON
4. 自动生成 API 文档

### 5.2 一个具体例子

```python
from pydantic import BaseModel, Field

class SearchRequest(BaseModel):
    query: str = Field(..., min_length=1, description="患者症状描述")
    top_k: int = Field(5, ge=1, le=20, description="返回结果数")
```

意思是：

- `query` 必须是字符串，至少 1 个字符（`...` 表示必填）
- `top_k` 是整数，默认 5，范围 1~20（`ge` = greater or equal，`le` = less or equal）

如果前端发来 `{"query": "", "top_k": 100}`，FastAPI 会**自动返回 422 错误**，业务函数根本不会被调用。

### 5.3 完整定义（`backend/schemas.py`）

8 个模型分三类：

**请求模型**（前端 → 后端）：

- `SearchRequest` — `/search` 的请求体
- `AnalyzeRequest` — `/analyze` 的请求体

**响应模型**（后端 → 前端）：

- `FormulaItem` — 单条方剂（10 个字段）
- `FewshotItem(FormulaItem)` — 继承方剂，多一个 `example_case` 医案文本
- `SearchResponse` — `/search` 的响应
- `AnalyzeResponse` — `/analyze` 的响应
- `KnowledgeCountResponse` — `/knowledge/count` 的响应
- `RebuildIndexResponse` — `/admin/rebuild-index` 的响应

### 5.4 为什么这么重要

三个价值：

1. **边界安全**：脏数据永远到不了业务逻辑，避免 `AttributeError: 'NoneType' has no attribute...` 这种运行时错误
2. **前后端契约**：前端团队看 `AnalyzeResponse` 就知道后端返几个字段、什么类型
3. **免费文档**：`/docs` 会自动显示每个字段的类型和描述

## 六、Task 3 · 应用生命周期钩子

**目标**：让后端启动时自动同步 SQLite + 建 Chroma 索引（相当于 V4 里 `@st.cache_resource` 干的事）。

### 6.1 什么是 lifespan

FastAPI 提供了一个"启动/关闭钩子"机制，你可以在应用启动前 / 关闭后跑一段代码。

`backend/lifespan.py`：

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI

from src.services.knowledge_service import sync_from_json
from src.services.retrieval_service import build_index


@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动时执行
    sqlite_count = sync_from_json()
    chroma_count = build_index(force_rebuild=False)
    logger.info(f"Knowledge base ready — SQLite: {sqlite_count}, Chroma: {chroma_count}")

    yield  # 应用运行期间

    # 关闭时执行
    logger.info("Backend shutdown.")
```

`yield` 之前 = 启动时跑；之后 = 关闭时跑。

### 6.2 挂载到 app

```python
app = FastAPI(
    ...
    lifespan=lifespan,  # ← 注入生命周期钩子
)
```

启动时会自动看到：

```text
Backend startup: syncing knowledge base...
Knowledge base ready — SQLite: 20, Chroma: 20
Application startup complete.
```

### 6.3 CORS 中间件

`main.py` 里还加了：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    ...
)
```

**为什么**：浏览器出于安全，默认禁止一个域名的页面访问另一个域名的 API。Streamlit（:8501）和 FastAPI（:8000）算不同"域"，不加这个前端就会报"跨域错误"。`allow_origins=["*"]` 是开发环境的宽松设置。

## 七、Task 4 · pytest 测试骨架

**目标**：搭建 pytest + FastAPI TestClient 环境，让每个接口都能被自动化测试。

### 7.1 为什么要写测试

不是"锦上添花"——测试是**重构的安全网**。有了测试，你以后动 `/search` 或 `/analyze` 时才敢下手。改完跑一遍 `pytest`，如果全绿就说明"至少没把已知功能改坏"。

### 7.2 `tests/conftest.py`

```python
import pytest
from fastapi.testclient import TestClient
from backend.main import app


@pytest.fixture(scope="session")
def client() -> TestClient:
    with TestClient(app) as c:
        yield c
```

- `TestClient` — FastAPI 提供的测试工具，**不需要真的启动服务器**，直接在内存里调接口
- `with TestClient(app)` — 会触发 lifespan（同步知识库、建索引）
- `scope="session"` — 整个测试进程共用一个 client，避免每个测试都重新初始化知识库（否则要慢 20 秒）

### 7.3 一个简单测试 `test_health.py`

```python
def test_health_returns_ok(client):
    response = client.get("/health")
    assert response.status_code == 200
    body = response.json()
    assert body["status"] == "ok"
```

pytest 会自动发现所有 `test_*.py` 里的 `test_*` 函数并执行。

### 7.4 运行

```powershell
pytest tests/ -v
```

看到全部 PASSED 就 OK。

## 八、Task 5 · POST /search

**目标**：把 V4 里的 `retrieval_service.search()` 暴露成 HTTP 接口。

### 8.1 路由文件 `backend/routers/search.py`

```python
from fastapi import APIRouter
from backend.schemas import SearchRequest, SearchResponse, FormulaItem
from src.services.retrieval_service import search as retrieval_search

router = APIRouter(tags=["search"])


@router.post("/search", response_model=SearchResponse)
def semantic_search(req: SearchRequest) -> SearchResponse:
    raw_results = retrieval_search(req.query, top_k=req.top_k)
    results = [FormulaItem(**item) for item in raw_results]
    return SearchResponse(
        query=req.query,
        top_k=req.top_k,
        results=results,
    )
```

**逐行解释**：

- `APIRouter` — 路由分组器。相关接口放一个文件，方便管理
- `@router.post("/search", response_model=SearchResponse)` — POST 方法，绑定响应模型
- `def semantic_search(req: SearchRequest)` — 参数类型是 `SearchRequest`，FastAPI 会**自动把请求体的 JSON 解析成对象**
- `[FormulaItem(**item) for item in raw_results]` — 把 `retrieval_service` 返回的 dict 列表转成 Pydantic 对象列表
- 返回 `SearchResponse` 对象，FastAPI 自动转 JSON

### 8.2 挂载到 app

`backend/main.py`：

```python
from backend.routers import search as search_router
app.include_router(search_router.router)
```

### 8.3 测试 `tests/test_search.py`

```python
def test_search_rejects_empty_query(client):
    response = client.post("/search", json={"query": "", "top_k": 5})
    assert response.status_code == 422  # Pydantic 自动拒绝
```

**注意**：这里不用自己写 `if not query: raise 400`，Pydantic 直接把 422 甩回去。

## 九、Task 6 · POST /analyze

**目标**：把 V4 里"检索 + Few-shot + LLM 生成"完整流水线暴露成一个 HTTP 接口。

### 9.1 路由文件 `backend/routers/analyze.py`

```python
@router.post("/analyze", response_model=AnalyzeResponse)
def analyze(req: AnalyzeRequest) -> AnalyzeResponse:
    try:
        retrieved = retrieval_search(req.query, top_k=req.top_k)
        fewshot = build_fewshot_examples(retrieved)
        analysis = generate_analysis(req.query, retrieved, fewshot)
    except RuntimeError as exc:
        raise HTTPException(status_code=503, detail=str(exc))
    except ValueError as exc:
        raise HTTPException(status_code=400, detail=str(exc))

    pipeline_steps = [...]

    return AnalyzeResponse(
        query=req.query,
        retrieved=[FormulaItem(**item) for item in retrieved],
        fewshot=[FewshotItem(**item) for item in fewshot],
        analysis=analysis,
        pipeline_steps=pipeline_steps,
    )
```

**关键点**：

- **一个接口 = 三步复合调用**：检索 → Few-shot → 生成
- **错误分类映射到 HTTP 状态码**：
  - `RuntimeError`（比如没配 API Key）→ 503（服务不可用）
  - `ValueError`（比如输入格式错）→ 400（请求错误）
  - Pydantic 校验失败 → 422（不用自己写）
  - 其他未捕获 → 500（服务器错误）

`HTTPException` 是 FastAPI 抛错的标准方式，会自动变成对应状态码的 JSON 响应。

### 9.2 测试骨架

```python
REQUIRES_LLM = pytest.mark.skipif(
    not os.getenv("DEEPSEEK_API_KEY"),
    reason="DEEPSEEK_API_KEY not configured",
)

@REQUIRES_LLM
def test_analyze_full_pipeline(client):
    response = client.post("/analyze", json={"query": "入睡困难...", "top_k": 5})

```

## 十二、Task 9 · 前端 API 客户端

**目标**：封装前端调后端的所有 HTTP 请求，Streamlit 里只调这些函数。

### 12.1 什么是 httpx

`httpx` 是 Python 里的 HTTP 客户端库（相当于浏览器的 fetch）。语法比标准库 `urllib` 好用，比老牌 `requests` 更现代化（支持 async）。

### 12.2 `config/settings.py` 新增

```python
BACKEND_BASE_URL: str = os.getenv("BACKEND_BASE_URL", "http://127.0.0.1:8000")
BACKEND_TIMEOUT: float = float(os.getenv("BACKEND_TIMEOUT", "120.0"))
```

超时给到 120 秒——因为 `/analyze` 要等 DeepSeek 返，慢的时候可能 30 秒。

### 12.3 客户端 `frontend/api_client.py`

```python
import httpx
from config.settings import BACKEND_BASE_URL, BACKEND_TIMEOUT


class BackendError(RuntimeError):
    pass


def _client() -> httpx.Client:
    return httpx.Client(base_url=BACKEND_BASE_URL, timeout=BACKEND_TIMEOUT)


def analyze(query: str, top_k: int = 5) -> dict:
    with _client() as c:
        r = c.post("/analyze", json={"query": query, "top_k": top_k})
        if r.status_code >= 400:
            raise BackendError(f"{r.status_code}: {r.text}")
        return r.json()
```

**逐行**：

- `_client()` — 工厂函数，每次返回一个新的 `httpx.Client`
- `with _client() as c:` — 上下文管理器，用完自动关连接
- `c.post("/analyze", json={...})` — 自动把 dict 变成 JSON body
- `r.json()` — 把响应 body 解析回 dict

前端所有跨网络的地方都在这一个文件里。UI 层再也不 import `openai` 或 `chromadb`。

## 十三、Task 10 · 新 Streamlit 前端

**目标**：把原 `app.py` 的 UI 代码搬过来，业务调用改成走 `api_client`。

### 13.1 前后对比

**V4** 里 UI 直接调 service：

```python
from src.services.retrieval_service import search

```

**V5** 里 UI 走 HTTP：

```python

```

**关键点**：Streamlit 代码里再没有 `sqlite3` / `chromadb` / `openai` 的导入。**UI 层完全不知道后端用什么技术栈**——这就是"接口驱动"的价值。

### 13.2 错误处理

```python
try:
    result = api_client.analyze(user_input, top_k=5)
except BackendError as exc:
    st.error(f"后端返回错误：{exc}")
except Exception as exc:
    st.error(f"后端调用失败：{exc}")
```

后端返 4xx/5xx → `BackendError`；网络断了 → `httpx` 的异常。前端友好地告诉用户"后端挂了"，而不是原地崩溃。

### 13.3 Sidebar 健康检查

```python
try:
    counts = api_client.knowledge_count()

    st.success("后端连接正常")
except Exception as exc:
    st.error(f"后端不可用：{exc}")
```

前端启动第一件事就检查后端能不能连上——用户一眼看见"服务是否 OK"。

## 十六、常见问题 FAQ

### Q1: 为什么不用 Django 或 Flask？

- **Flask** — 老牌但没有原生类型校验和自动文档
- **Django** — 太重（自带 ORM/后台/模板），我们只要 API
- **FastAPI** — 类型驱动、自动文档、性能好、异步支持

对小型 AI 后端服务，FastAPI 是最佳选择。

### Q2: 为什么保留 Streamlit，不换 React？

- **学习曲线**：React 需要额外学 JavaScript/JSX/组件生命周期
- **前后端联调复杂度**：真正的前后端分离需要 CORS/CSRF/build 打包/静态资源托管
- **原型阶段的目标**：先证明架构可行，前端好看是下一阶段的事

未来如果要"全栈重构"，把 Streamlit 换成 React/Next.js，后端 API 完全不用改——**这就是分层架构的红利**。

### Q3: pytest TestClient 和真正启动 uvicorn 有什么区别？

- `TestClient` 在**同一进程内**用 ASGI 协议直接调用 app 对象，不走 TCP，不真的绑定端口
- 真启动 `uvicorn` 是完整的服务器进程，绑定端口，走网络协议栈

对测试来说 `TestClient` 更快、更简单；对手动验证或性能测试就要真启动。

### Q4: 为什么后端启动要等 5 秒？

首次启动需要：

1. 从 JSON 读 20 条数据 → SQLite（毫秒级）
2. 调 DashScope Embedding API 把 20 条文本变成向量（几秒到十几秒，看网络）
3. 写入 Chroma 索引（毫秒级）

第一次跑完，Chroma 会持久化到 `data/vector_store/`，后续启动只是校验条数，秒级完成。

### Q5: 生产环境该改哪些地方？

- `--reload` 去掉（生产不需要热重载）
- `CORS allow_origins=["*"]` 改成具体的前端域名（比如 `["https://tcm.hospital.example.com"]`）
- `--host` 改成 `0.0.0.0`（对外提供服务）
- 前面加 Nginx 反向代理 + HTTPS
- 换成 `gunicorn + uvicorn.workers.UvicornWorker` 起多进程
- 换 SQLite 为 Postgres（若多用户并发写）
- 加日志聚合、监控、限流

第五阶段先跑通，这些是"生产化"的下一步。

### Q6: 前端为什么用 `httpx` 不用 `requests`？

- `requests` 是老牌同步库，Streamlit 里其实也能用
- `httpx` API 兼容 `requests`，但**支持异步**，未来要用 async 前端（比如 FastAPI 前端 + Server-Sent Events 流式返 LLM 结果）时不用换库
- 也是 FastAPI `TestClient` 底层默认用的库，统一版本减少依赖冲突

### Q7: `Field(..., min_length=1)` 里的 `...` 是什么

Python 里 `...` 是 `Ellipsis` 对象。Pydantic 约定用它表示"这个字段必填"。等价于说"没有默认值"。

如果你写 `query: str = Field("默认值")`，就表示 `query` 可以不传，不传就是"默认值"。
